# 攜手基地｜產品需求文件 PRD v2.0

**產品方向：以線上遊戲為媒介的友誼形成支持系統**  
**文件狀態：Draft｜新一版產品方向與 PoC 規格**  
**版本日期：2026-10-28**  
**產品階段：可互動 UI PoC；不要求第一階段串接真實遊戲伺服器**

> **本版核心決策：** 將「攜手基地」從以報名、排程與行政追蹤為主的服務管理工具，調整為「固定小組共同經營一個持續發展的遊戲世界」的友誼支持系統。活動管理仍需要，但退居支援層；參與者與同伴共同遊玩、互相影響、累積共同記憶並決定下次相聚的體驗，才是產品主體。

## 0. 本版決策摘要

### 0.1 產品一句話

「攜手基地」使用既有多人線上遊戲作為共同活動空間，透過固定小組、持續共同作品、可切換的參與方式、低壓力交流與自願的後續邀請，支持成年行動障礙者從反覆相遇逐步發展同儕友誼，並在有意願時降低關係延伸至線下生活的障礙。

### 0.2 系統要扮演的角色

系統不是遊戲本體，也不是單純的報名表單或交友配對平台。它是「友誼發展支持層」，負責：

1. **維持關係的連續性：** 讓相同小組能回到同一個共同世界，延續上次的成果與計畫。
2. **設計有互惠機會的遊戲活動：** 讓成員需要一起討論、選擇、協作或互相幫助；不同操作及溝通方式都能對成果產生真實影響。
3. **提供低壓力的社交空間：** 任務之外，允許成員自然相處；不強迫分享私事，也不要求語音或交換聯絡方式。
4. **協助關係延續：** 保存必要的共同回憶、支持再次邀請，並在成員自願時提供線下共同活動的協調入口。
5. **維持參與安全與可及性：** 提供求助、暫停、切換方式、主持人介入及私密的參與支持設定。

### 0.3 本版不做什麼

- 不開發新遊戲、不取代 Minecraft 或其他既有遊戲。
- PoC 不實作真正的多人即時同步、Minecraft 伺服器串接、即時通訊或自動通知；以明確標示的模擬互動展示完整體驗。
- 不用 AI 分析聊天內容、推測友誼強弱、排名成員或自動推薦誰應該成為朋友。
- 不以出席率、遊玩時數、私人聯絡方式交換或線下見面作為單一成功標準。
- 不把身心障礙者預設成被協助者，也不依障礙類型固定分派角色。

## 1. 問題定義與設計依據

### 1.1 要解決的核心問題

成年行動障礙者可能因移動、交通、體力、場地可及性或外出安排等因素，較難穩定參與實體社交活動。線上遊戲可以提供遠端共同活動的機會，但「同時在線」不等於「建立友誼」；一次任務完成也不代表成員會再相聚、主動關心彼此，或在生活中形成可互相支持的關係。

本產品要處理的核心問題是：

**如何讓固定小組在可及、安全與自主的條件下，反覆經歷有意義的共同遊戲，逐步產生熟悉感、互惠互動與共同記憶，並在雙方／多方自願時，讓關係有機會延伸到遊戲之外及線下生活？**

### 1.2 目前版本與新版本的差異

| 面向 | 原 PoC 主要著力點 | v2.0 新方向 |
|---|---|---|
| 核心價值 | 把報名、確認、分組、排程、回饋與追蹤流程跑通 | 支持固定同伴反覆相聚、共同創作、互惠互動與關係延續 |
| 參與者主要畫面 | 表單、狀態、場次資訊、問題回報 | 小組基地、共同任務、參與方式、共同記憶、下次計畫 |
| 活動本身 | 外部遊戲活動的資訊與加入指引 | 由產品協助編排的共同遊戲體驗與低壓力交流節奏 |
| 管理者工作 | 審核、排程、紀錄和儀表板 | 設計任務、維持小組連續性、支援不同參與方式、協助安全和關係延續 |
| 成效判斷 | 以服務流程完成、出席、回饋為主 | 同時觀察重複參與、互惠互動、主觀連結感與自願延續意願 |

### 1.3 桌面研究提供的設計線索

以下研究只支持設計假說，不足以證明本產品一定有效：

- 一項 2023 年針對身體障礙青少年的 VR 多人遊戲可行性研究，納入 12 人、8 人完成；完成者中 7 人表示在小組中交到朋友、4 人表示課外也曾和同伴一起玩，但孤獨感前後測未見差異。可借鏡的是有主持的同儕遊戲、重複活動與關係延續，不應把結果直接外推到成年台灣使用者。見參考資料 [R1]。
- 2023 年「Social accessibility in multiplayer games」提出，多人遊戲可及性除了控制器、介面等技術面，也包含能否與他人溝通、參與群體與遊戲文化；提供多元溝通選項有其重要性。見 [R2]。
- 2024 年針對柬埔寨身體障礙成年人的 Friendship Group 研究，以 8 週同儕團體比較線上及面對面形式，報告兩種形式在該情境下具有可行性與可接受性。此研究不是遊戲介入，因此僅借鏡固定週期、同儕帶領和線上參與支援。見 [R3]。
- 2026 年線上桌上角色扮演遊戲研究發現，參與者對團體的支持感、正向感受和社會相容性感受與幸福感等指標有關聯；這是調查研究，不能證明遊戲造成該結果。可借鏡共同敘事、共享群體身分與持續的團體故事。見 [R4]。

### 1.4 本 PRD 的證據界線

本 PRD 將研究轉化為可測試的產品假說。研究中的參與者比例或心理量表結果，不是本服務的預期成效，也不應直接作為對外宣稱。原 PoC 的儀表板數據為系統測試用種子／模擬資料，不代表真實參與者或實際成效。任何模擬資料必須在介面及展示說明中標示為「示範資料」。

## 2. 目標、對象與成功定義

### 2.1 主要服務對象

年滿 18 歲，因肢體障礙或其他持續性移動功能限制，實際上較難外出或穩定參與實體同儕活動的成人。設計應以參與者自己描述的活動、設備、操作、溝通和支持需求為準，不要求在小組中公開診斷或醫療資訊。

### 2.2 使用者角色

- **參與者：** 選擇參與方式、和小組共同遊戲、提出想法、接受或提供協助、設定社交界線，並決定是否延續關係。
- **主持人／社群引導者：** 帶領活動、提供選擇與參與支援、維持安全、協助小組保留共同計畫；不替成員決定誰應該成為朋友。
- **服務管理者：** 負責招募、安排固定小組、活動管理、必要的安全事件追蹤及服務成效摘要。
- **PoC 展示者／測試者：** 使用虛構種子資料走過主要情境；不將測試角色或模擬互動視為真實服務證據。

### 2.3 產品目標

1. 讓參與者容易回到相同小組與持續發展的共同遊戲世界。
2. 讓每場活動至少有一個需要共同決策、協作或互相回應的目標。
3. 讓每位成員可自主選擇、切換參與方式，並對共同成果產生實質影響。
4. 讓遊戲任務之外存在低壓力的相處時刻，而非強迫社交或公開個人資訊。
5. 支援共同經歷的延續、下次活動的共同決定，以及自願的線下活動探索。
6. 保留必要的服務營運和安全管理能力，但不讓行政儀表板成為產品主體。

### 2.4 成功的分層定義

- **PoC 成功：** 測試者能操作並理解核心友誼支持流程；模擬狀態有清楚標示；主要功能有可見的狀態變化。
- **試辦可行：** 真實參與者能以適合自己的方式參與，願意再次回到同一小組，活動中實際出現共同決策、互助或自主延續行為。
- **中長期成果假說：** 部分成員在自願前提下維持遊戲外聯繫、參與其他共同活動，或感受到可運用的情緒支持、資訊、陪伴或社會機會。

產品不可宣稱已降低孤獨、治療心理問題、建立友誼或提升線下社會資本，除非後續研究設計與資料足以支持該主張。

## 3. 核心產品模型：共同世界 + 互惠任務 + 關係延續

### 3.1 核心機制 A：共同世界持續存在

小組每次活動回到同一個遊戲世界／共同作品。每次聚會都接續上一回合的選擇、建設或故事，而不是每場活動完全重置。

**產品要求：**
- 每個小組有一個「基地」頁，顯示共同目標、最近成果、未完成的共同事項、下一次活動與小組自己決定的下一步。
- 共同成果可以是 Minecraft Creative 的基地、花園、博物館、交通系統或其他可持續擴充的作品；遊戲類型可替換，產品需求不應綁死於 Minecraft。
- 對成果的歸屬以小組為主。可以選擇記錄個人貢獻，但不得以貢獻數量排名成員。

### 3.2 核心機制 B：互相影響的合作任務

每次活動設定一個團隊目標，任務必須有成員之間的互動理由，例如共同選擇設計、提出提案並討論、協調資源、請求支援、合併不同想法或一起解決問題。

**任務規格：**
- 每個任務都要有清楚的共同目標和可辨識的共同成果。
- 每個任務至少提供兩種有意義的貢獻方式；例如直接操作遊戲、選擇設計、整理素材、提出提案、文字回應、語音討論或協助規劃。這些是選項，不是按障礙類型固定分派的角色。
- 任務允許成員中途換方式、暫停、請求協助或稍後回來，不用因而退出整場活動。
- MVP 不要求即時遊戲狀態整合；可以用任務板、提案、投票、模擬貢獻紀錄和共同成果頁展示機制。
- 不使用倒數計時或速度競賽作為核心完成條件。

### 3.3 核心機制 C：任務以外的低壓力相處

每場活動在任務前後保留可以自由交流的時間。可以談遊戲、分享興趣或單純一起待著，不要求每個人都發言或揭露私人生活。

**產品要求：**
- 提供可選擇、可跳過的開場問題與收尾問題；不出現強制分享創傷、健康、家庭或聯絡資料的問題。
- 參與者可以選擇文字、語音或不回答；主持人不可把沉默自動解讀為不投入。
- 共同回顧關注「我們一起做了什麼、哪個想法被採用、下次想接續什麼」，而不是給成員打友誼分數。

### 3.4 核心機制 D：關係延續與自願的線下橋接

活動結束時，由成員共同決定下一次要延續的事項。當小組有意願時，可以探索其他線上活動或線下聚會，但不設置強迫的「升級關係」流程。

**產品要求：**
- 可以建立下一次小組活動的共同提案／選擇，而不是由系統直接替成員決定。
- 活動外聯繫採自願同意；不得把分享私人電話、社群帳號或真實姓名作為入組或完成活動的條件。
- 線下活動提案應先顯示「活動方式、地點／交通待確認、可及性需求、是否需要陪同、費用資訊待確認」等欄位；不得在尚未確認時聲稱地點可及或活動已成行。
- 若沒有成員想要線下聚會，系統提供替代的線上共同活動選項，不將其視為失敗。
- PoC 可模擬線下活動提案與需求確認；真實場地查核、交通協調、聯絡方式交換及通知不在第一階段實作。

## 4. 服務與活動設計

### 4.1 建議試辦基準（規劃假設）

- 小組規模：6–8 位參與者；實際規模視主持量能與平台限制調整。
- 週期：每週一次，連續 8 週；此為試辦設計假設，不是產品硬性限制。
- 單場時長：約 75–90 分鐘；提供彈性休息與提早離場方式。
- 人力：每場至少明確指定主持責任與安全事件備援；能否由同一人兼任需依實際服務量能決定。
- 遊戲：以 Minecraft Creative 模式作為候選，但正式選用前需確認設備、控制方式、平台費用／授權、私人世界設定和實際可及性。

### 4.2 每場活動的建議節奏

| 階段 | 建議時間 | 目的 | 系統支援 |
|---|---:|---|---|
| 回到基地／輕量報到 | 5–10 分鐘 | 重新進入同一團體、確認今天狀態 | 顯示共同世界、上次進度、可用參與方式；允許選擇只旁聽／先休息 |
| 共同選擇今天目標 | 5–10 分鐘 | 讓成員對活動有自主權 | 顯示 2–3 個任務選項，記錄小組共同選擇 |
| 合作任務 | 30–40 分鐘 | 創造共同決策、協作與互助機會 | 任務板、提案／回應、貢獻方式選擇、求助／暫停／換方式 |
| 自由相處／共同回顧 | 10–15 分鐘 | 讓互動有機會超越任務本身 | 可跳過的對話提示、共同成果、可選的互相致謝 |
| 接續下一次 | 5–10 分鐘 | 讓再次相聚有具體理由 | 記錄下次共同目標、成員自願認領的下一步與時間偏好 |

以上時間只是主持指引，不作為強制進度表。若成員需要更多休息、較慢節奏或提前結束，主持人可以調整。

### 4.3 八週共同世界進程範例

| 週次 | 團體發展重點 | 範例活動 | 不應做的事 |
|---|---|---|---|
| 第 1 週 | 安全感與共同選擇 | 一起決定基地主題、命名共同空間 | 強迫自我介紹或透露障礙細節 |
| 第 2 週 | 熟悉彼此偏好 | 共同設計休息區、收藏成員自願分享的興趣 | 將未發言者判定為不投入 |
| 第 3 週 | 互相影響與求助 | 每位成員提出一個想法，小組選擇並整合 | 讓主持人或技術最佳者包辦成果 |
| 第 4 週 | 接續共同專案 | 延續上週建設，討論哪一部分需要修改 | 每週重置成果、失去共同記憶 |
| 第 5 週 | 共同故事與身份 | 為基地建立故事、標誌或共同規則 | 把故事設定為披露個人創傷的活動 |
| 第 6 週 | 成員主導 | 讓成員提出下一個任務並共同決定 | 把所有發起責任固定交給主持人 |
| 第 7 週 | 延伸共同活動的可能 | 小組選擇繼續遊戲、換遊戲或探索其他活動 | 預設一定要交換私人聯絡方式或見面 |
| 第 8 週 | 回顧與自願延續 | 回顧共同成果，選擇是否繼續小組活動 | 將拒絕線下活動視為計畫失敗 |

這是一套可供原型示範的教學腳本，不是對友誼形成順序的保證。成員的關係發展速度不同，主持人應依實際情況調整。

## 5. 主要使用流程

### 5.1 參與者核心旅程

1. **選擇參與方式：** 選擇顯示名稱、可用溝通管道、操作／參與偏好、休息方式與社交界線。只收集安排活動所需資料。
2. **進入小組基地：** 查看固定小組、共同世界、近期成果、下次活動與求助入口。
3. **加入當次任務：** 查看目標、可用貢獻方式、活動節奏及是否可以中途休息。
4. **實際參與共同決策：** 提出想法、回應他人提案、選擇方案、請求協助或切換參與方式；PoC 以模擬互動展示。
5. **看到共同成果：** 查看小組最後的決定與成果；個人貢獻是否署名由參與者選擇。
6. **低壓力回顧：** 回答可跳過的問題，例如「今天哪個決定是大家一起完成的？」或「下次想接著做什麼？」
7. **建立下次相聚的理由：** 參與者查看並共同選擇下一次的延續事項；可自願開啟其他共同活動提案。
8. **自願延伸：** 有意願時參與遊戲外聊天或線下活動規劃；不分享個人聯絡方式也能繼續參與小組。

### 5.2 主持人核心旅程

1. 選擇任務範本，設定共同目標、可用參與方式、預計節奏與可選反思問題。
2. 活動前檢視參與支持設定，只看到履行主持工作所需的資訊，不公開診斷或不必要的私人內容。
3. 活動中引導共同決策、觀察是否有人被排除，並允許成員求助、休息、切換方式或稍後回歸。
4. 需要時暫停活動、處理技術或安全事件；敏感描述只對授權管理角色可見。
5. 活動後記錄共同成果、任務完成情況及簡短的互動觀察，不記錄完整私人聊天作為預設要求。
6. 檢視小組是否需要調整節奏、任務難度或支持方式；不可用儀表板對成員的友誼能力或社交價值排名。

## 6. 功能需求

優先級定義：**P0** = 新 PoC 核心，必須可演示；**P1** = 有限試辦前優先補足；**P2** = 後續可評估。PoC 使用種子資料與本地模擬時，必須清楚標示，不得聲稱已具備即時多人或正式後端能力。

**FR-01｜小組基地首頁｜P0**  
參與者能看到自己的固定小組、共同世界摘要、上次成果、下次活動與當前共同目標；資訊不可只是一份場次清單。

**FR-02｜共同世界／成果延續｜P0**  
能查看至少一項既有共同成果、一項待延續事項及一項小組共同決定；刷新或切頁後 PoC 狀態依原型設定保存，並說明保存方式。

**FR-03｜合作任務板｜P0**  
任務包含團隊目標、共同決定、成果描述及至少兩種有意義的貢獻方式；不得把所有任務設計成純個人勾選清單。

**FR-04｜提案與共同決策｜P0**  
參與者可新增／選擇提案，查看其他成員的模擬提案並完成投票或排序；結果能反映至共同任務狀態。

**FR-05｜貢獻方式選擇與切換｜P0**  
參與者可從任務提供的方式中選擇或切換；介面不依診斷或障礙類型自動指定角色，且不把直接操作遊戲視為唯一有效貢獻。

**FR-06｜求助／暫停／重新加入｜P0**  
參與者可啟動求助、暫停或改用另一參與方式；系統顯示收到請求及下一步，不要求公開說明診斷。

**FR-07｜低壓力交流與回顧｜P0**  
任務前後提供可選的開場／收尾提示；每題允許跳過；不要求揭露敏感資料。

**FR-08｜共同記憶／活動摘要｜P0**  
活動後生成可查看的小組摘要，至少包含共同完成／決定的事項和下次可接續內容；不預設保存完整聊天紀錄。

**FR-09｜下次活動共同計畫｜P0**  
成員能選擇、提出或支持下一次活動目標；參與者端顯示目前決定及待確認事項。

**FR-10｜參與偏好與支持設定｜P0**  
可設定文字／語音偏好、休息／回歸方式與參與模式；相關資料只有履行服務所需的授權人員可查看。

**FR-11｜主持人任務編排器｜P0**  
主持人能建立／選取任務，填寫團隊目標、貢獻方式、非強制性提示與共同成果；發布前能檢查必要欄位。

**FR-12｜主持人活動控制台｜P0**  
可查看成員參與狀態、任務進度、待回應求助與安全事件；畫面不得用單一分數排序成員的社交表現。

**FR-13｜固定小組與場次管理｜P0**  
管理者仍可建立固定小組、場次、主持人與活動指引；此功能支援核心體驗，不應佔據參與者首頁的主要位置。

**FR-14｜安全事件回報與管理｜P0**  
參與者能私密回報技術或互動安全問題；管理者能更新處理狀態；敏感內容不出現在小組公開頁面。

**FR-15｜自願的線下／遊戲外活動提案｜P1（PoC 可模擬）**  
成員可提出其他共同活動並表達意願；介面明示地點、交通與可及性仍待確認；拒絕或略過不影響一般參與權。

**FR-16｜活動提醒｜P1**  
PoC 僅展示站內提醒狀態；未串接外部管道不得顯示為已寄送簡訊、Email 或推播。

**FR-17｜匯總成效摘要｜P1**  
管理者能查看服務執行與小組層級互動摘要，含定義、期間和樣本數；無真實資料時顯示「示範資料」。

**FR-18｜匯出資料｜P2**  
後續若需要匯出，以彙總資料為主；個人敏感資訊不應預設出現在匯出內容。

## 7. 非功能需求與服務規則

### 7.1 可及性

- 核心流程可用鍵盤操作；焦點順序合理且焦點狀態清楚。
- 所有互動元件需有可理解的文字標籤；狀態不得只靠顏色傳達。
- 版面支援文字放大、足夠對比與清楚的錯誤訊息；避免閃爍、強制倒數與時間壓力。
- 重要活動資訊需同時提供文字版本；語音不是唯一的參與或求助管道。
- 設計目標可參考 WCAG 2.2 AA；在完成實際檢查或稽核前，不得宣稱已符合該標準。
- 「可及性確認」用於找到適當調整與替代方式，不得成為因身心障礙而自動拒絕參與的門檻。若某個平台確實無法配合，應提供具體原因與替代方案。

### 7.2 隱私與資料最小化

- 公開顯示名稱與報名／聯絡資料分開處理。
- 不要求公開診斷、醫療史、照護細節或真實姓名。
- 不預設監看或保存完整聊天內容；友誼形成不以聊天分析或關係分數判定。
- 參與者可以選擇不公開個人貢獻署名，不會因此失去參與資格。
- PoC 只使用虛構種子資料；不可把真實敏感資料存進瀏覽器 LocalStorage 來展示。
- 正式服務另需定義告知與同意、角色權限、傳輸／儲存保護、存取紀錄、保存期限、刪除流程及事件應變方式。若 PoC 未有正式後端或加密，不得宣稱資料已加密或受到正式生產環境保護。

### 7.3 社群安全與主持規則

- 小組採邀請／經確認加入；活動前提供清楚的互動規則與求助方式。
- 參與者可拒絕私聊、交換聯絡方式或線下邀請，不必提出理由。
- 主持人可暫停活動、限制不當互動、調整分組或移除違規成員，並依服務政策記錄後續處理。
- 對技術困難和安全事件使用不同處理流程；不得要求受影響者在公開小組解釋細節。
- 任何未成年人功能均不屬於本版本目標範圍；本版服務對象為成年人。

### 7.4 技術與原型誠實性

- PoC 可以沿用現有 React/Vite SPA 與本地模擬資料模式，但應以明確標籤表示「示範模式／模擬成員／模擬同步」。
- 任務提案、投票、貢獻動態或通知若是本地模擬，應能點擊並看到狀態變化，但不得讓展示者描述為真實多人同步。
- 第一版不要求 Minecraft API、伺服器整合、Discord 整合或即時通訊。加入遊戲可以只展示指引與示意狀態。
- 核心互動頁需要處理空狀態、載入／提交回饋、錯誤狀態和返回路徑，不能只有靜態畫面。

## 8. 成效假說與衡量方式

### 8.1 作用模型

固定小組與共同世界 → 反覆相遇和共同記憶 → 有互相影響的合作與低壓力交流 → 熟悉感、互惠與主動互動增加 → 部分關係延伸到遊戲之外 → 在有意願且障礙可處理時，可能形成線下社會支持或活動機會。

每個箭頭都是需要驗證的假說。不能將參與率直接當作友誼形成，也不能將線上互動直接推論為線下社會資本。

### 8.2 指標分層

| 層級 | 指標 | 建議取得方式 | 解讀限制 |
|---|---|---|---|
| 服務執行 | 場次舉辦、出席、重複參與、取消與回歸情況 | 場次紀錄 | 反映可行性，不直接等於友誼 |
| 可及性 | 使用替代參與方式、求助／暫停是否有回應、因操作／溝通障礙而無法參與的情況 | 自願回饋及主持人摘要 | 不應用來給個人貼標籤 |
| 互動過程 | 是否發生共同決策、互相幫助／請求幫助、成員發起提案、同伴間直接互動 | 主持人用簡短分類記錄；必要時匿名匯總 | 不保存完整聊天紀錄作為預設量測方法 |
| 主觀連結 | 是否覺得認識同伴、被團體接納、願意再次和同一小組活動 | 自願的簡短自評 | 需標明是自陳，不是客觀友誼判定 |
| 關係延續 | 是否自願在其他時間一起遊戲、持續聯絡或共同規劃活動 | 自願追蹤，不強制收集聯絡對象身分 | 不聯絡不等於失敗；隱私優先 |
| 線下社會資本 | 是否新增可提供資訊、陪伴、支持或活動機會的關係；自願線下活動是否實際可行 | 自願追蹤與訪談／回饋，需另行規劃 | 小型試辦只能產生初步訊號，不能證明因果 |
| 安全 | 事件類型、是否及時接收、是否有後續措施 | 私密事件紀錄 | 回報數較高不一定代表更不安全，也可能代表更有信心回報 |

### 8.3 成效儀表板規則

- 清楚區分真實資料、測試種子資料與模擬互動。
- 無真實試辦資料時，頁面需顯示「示範資料，非實際服務成效」；不得使用會讓人誤認為真實成果的圖表標題。
- 每個比率顯示分子、分母、期間與排除規則。
- 不輸出個人「友誼分數」、社交排名或「最受歡迎成員」列表。
- 缺席、未回覆和拒絕線下邀請不可自動視為負面意願。

## 9. PoC 必須演示的端到端情境

### 情境名稱：從再次相聚到接續共同計畫

**初始狀態：** 小組已有 4 位示範成員，正在共同打造一個持續發展的基地。每位成員有不同的參與偏好，但畫面不推測或展示其診斷。

1. 參與者進入「我的基地」，看到同一小組、上次成果「基地休息區」、下次活動及未完成的共同決定。
2. 參與者打開任務板，查看共同目標「一起決定並建設基地入口」，可選擇直接操作、提出設計選項、整理資源或文字／語音參與討論。
3. 參與者提交一個入口設計提案；介面顯示兩位示範成員的其他提案，並由小組投票／排序。投票結果更新共同決定。
4. 其中一位示範成員選擇「我需要換一種參與方式」，將直接操作切換成設計選擇；畫面確認已切換，不顯示診斷或個人原因。
5. 另一位成員點選「請求協助」，主持人端看到待回應事項並回應；參與者端顯示已收到協助。
6. 活動結束後產生共同摘要：今天選定的入口、採用的設計想法、尚待完成的項目與下次可接續內容。
7. 成員選擇一個可跳過的回顧題，並共同選出下次想做的項目；系統更新「下次計畫」。
8. 主持人展示小組層級互動摘要，例如「本場有共同決策、提案回應與求助處理」；不可產生個人友誼分數。
9. 展示者開啟「其他共同活動」提案，成員可以選擇「有興趣」、「暫不考慮」或「想先繼續線上活動」。頁面明示此為意願蒐集／模擬狀態，並未建立真實活動或交換聯絡方式。

### PoC 驗收條件

- 能完整走完上述 9 個步驟，並在每個主要操作後看到明確的狀態變化。
- 任務板不是純表單：至少有提案、他人提案、共同決策結果、貢獻方式切換和共同成果延續。
- 至少兩種貢獻方式會影響任務結果；不得只用裝飾性選項假裝多元參與。
- 求助、暫停／換方式、共同摘要、下次計畫都有可見行為與結果。
- 主持人能從活動任務設定到活動後摘要完成一個閉環。
- 線下活動提案是選擇性的，拒絕不會阻擋其他流程。
- 所有示範成員、互動、指標皆標示為虛構／模擬資料，不得被描述為真實測試成效。

## 10. 開發範圍與建議次序

### Phase 1｜讓友誼支持核心體驗可以被演示（先做）

1. 小組基地首頁與持續共同成果。
2. 合作任務板、提案／共同決策與多元貢獻方式。
3. 求助、暫停、換方式與主持人回應。
4. 共同記憶、可跳過的回顧與下次活動計畫。
5. 虛構資料標示、基本可及性與安全規則。

### Phase 2｜補足服務營運能力

1. 固定小組和場次管理。
2. 主持人任務範本與活動控制台。
3. 私密事件管理、出席及自願回饋。
4. 小組層級的服務與互動摘要。

### Phase 3｜有限試辦前再決定

1. 真實通知與日曆整合。
2. 遊戲平台與通訊工具的實際選擇／串接。
3. 線下活動的可及性查核、交通和陪同需求協調。
4. 正式資料庫、帳號權限、資料保存與刪除、資安檢查。
5. 試辦評估設計與量表選擇。

### 本版不應優先做的項目

- 重寫完整報名與行政儀表板而不改變參與者的核心體驗。
- 自建聊天、視訊、遊戲引擎或即時多人服務。
- 自動配對好友、推估情緒或用 AI 判斷誰與誰友好。
- 將所有活動都做成固定角色分工或分數競賽。
- 把線下見面人數設定成 PoC 的通過條件。

## 11. 主要風險與應對

| 風險 | 可能結果 | 應對方式 |
|---|---|---|
| 共同任務退化為個人作業 | 成員同時在線但互動很少 | 每個任務設計共同決策、提案回應或資源／想法整合，驗收時要求至少一項互相依賴的互動 |
| 操作能力高的人包辦 | 其他成員被動旁觀，社交地位不平等 | 多元貢獻方式必須能改變共同成果；主持人觀察分工，允許切換而不固定角色 |
| 社交引導過度刻意 | 成員覺得像上課或被要求交朋友 | 對話提示可跳過；共同任務優先；保留沉默、旁觀及自然聊天的空間 |
| 平台不適合部分參與者 | 產生新的排除 | 先做小型操作確認，允許替代方式；不要把檢核當作自動淘汰機制 |
| 線下活動帶來安全／可及性風險 | 參與者承受壓力或遇到實際障礙 | 只有自願提出後才進入規劃；確認地點、交通、陪同、費用與公共安全資訊；不強迫私下見面 |
| 管理者工作量過高 | 主持人無法維持關係連續性 | 使用任務範本、共同摘要與明確的活動節奏；先限制小組數和功能範圍 |
| PoC 被誤認為正式服務 | 模擬功能、資安或數據被過度宣稱 | 每個模擬頁／儀表板明示資料狀態；對外描述分開說明已實作、模擬與待整合功能 |
| 小組成員中途離開 | 共同世界或關係中斷 | 允許暫停、重新加入或調整任務；不公開缺席原因，不把缺席自動判為不感興趣 |

## 12. 待決策事項

以下事項不必阻止第一版 UI PoC，但在真實試辦前必須定案：

1. **遊戲選型：** Minecraft Creative 是候選，不是已證實最適合所有參與者的平台；需確認設備、控制方式、授權、私人空間和主持人管理能力。
2. **試辦規模及週期：** 6–8 人、每週一次、8 週只是初始假設；需按主持量能與實際使用情況調整。
3. **支援方式：** 活動主持、技術協助及安全事件備援的責任分工。
4. **外部通訊：** 是否允許／提供哪種遊戲外交流方式，以及如何取得同意與保護個資。
5. **線下延伸：** 是否由服務團隊主辦共同活動，或僅提供資訊與協調工具；不可在責任未定時暗示平台會保障活動安全。
6. **成效評估：** 試辦要採用哪些自評題目、是否使用正式量表，以及保存和刪除資料的方式。

## 13. 名詞定義

- **共同世界：** 小組跨多次活動持續經營的遊戲空間或共同作品；不限定特定遊戲。
- **共同任務：** 需要成員之間共同選擇、協作、回應或整合成果的活動目標。
- **貢獻方式：** 參與者用來影響共同成果的途徑，例如直接操作、提案、選擇、整理、文字或語音交流；不按障礙類型固定分配。
- **共同記憶：** 團體共同完成的事、重要選擇與下一步；不是完整聊天紀錄。
- **社交可及性：** 參與者能否與其他人溝通、對群體活動產生影響並被納入團體，不只看介面或控制器是否能操作。
- **線下社會資本：** 透過關係取得的情緒支持、資訊、陪伴、互助或活動機會；不等於實際見面次數。
